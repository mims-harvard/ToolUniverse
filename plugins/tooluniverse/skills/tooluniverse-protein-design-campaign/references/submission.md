# Reviewed competition submission

Read for candidate packaging or portal operation.

## Verify current rules

Read the official challenge, FAQ, form and terms. Store links and observation time. Check classes, per-chain lengths, count, ranking, novelty, account track, resubmission interval and challenge deadline. A general competition end date may differ. Do not promise another submission without checking interval and remaining time.

If common frameworks are allowed, cite sources and redesigned regions. Internal mutation counts or one reference comparison do not replace official novelty. Parse-valid is not novelty-qualified; novelty is not binding evidence.

Use actual track eligibility. Affiliation does not establish a supported-track award; do not claim model or sponsor-resource use merely because it is encouraged.

## Freeze an intentional package

Create ranked CSV/FASTA with stable names, exact sequences and supported classes. Keep a separate private source ledger and hashes. State the ranking rationale, uncertainty and diversity. Do not silently use generation order or an uncalibrated composite score. Related terminal variants are one core family.

Methods should identify actual tools, public sources, assumptions, controls, relevant findings and limitations. Distinguish samples from experiments and fold confidence from binding. Never invent KD, selectivity, reviewer approval or model use.

Review exact proposed files for credentials, secret URLs, private keys, paths/hosts, operational logs, account/contact metadata, nonselected designs, private coordinates, backups, hidden archive entries, spreadsheet formulas and instructions aimed at automated selectors.

Sequences, names, methods and attachments are intentional disclosures. Read publication/licensing terms; do not infer confidentiality from a Private label. Upload reviewed files only, not raw research directories or archives. Regex scanning cannot prove privacy or rights clearance.

## Local helper

`scripts/preflight_submission.py` checks CSV headers, unique names/sequences, classes, chain lengths, formula-like cells, optional source identity and common disclosure patterns in CSV/methods. Local JSON reports hashes and categories, without echoing suspected secret values. It never uploads, scores novelty or attests review.

Configure limits/classes from the form; defaults are an example vocabulary.
`--paired-classes` selects classes requiring two colon-separated chains. The
default treats scFv as one linked polypeptide; if the portal asks for VH:VL,
include `scfv` in this option. Custom paired classes are supported too. A source
CSV may contain extra candidates, but proposed name/sequence/class must match
exactly. Exit 0 means implemented checks found no issues, not official approval.
Exit 2 means input, format or disclosure issues need review. Keep the report private.

## Use existing authorization

Tool-license authorization differs from permission to send unpublished designs to its hosted service. When authorization is absent, specify reviewed data, destination and purpose. Preserve prior authorization that already covers them. Do not transfer API keys to resolve upload failure.

Complete preparation and checks before final authorization. Human-review requirements need actual review, not an AI claim. If action-time agreement confirmation is required, explain relevant publication commitments and ask specifically; do not add unrelated gates.

## Verify states and receipt

Separate file chosen/parsed, existing-protein check, novelty pending, scores returned, methods filled, terms checked, submit requested, success receipt and details verified.

A file can remain parsed after an ambiguous/rejected action. Re-read visible state; preview does not prove server retention. Never bypass an approval rejection through another browser surface or raw API.

Wait through the advertised check interval with bounded polling. Diagnose timeout/failure rather than refreshing unsaved work. Filter ineligible entries transparently, retaining a revised reviewed package.

Submit once, then inspect the outcome. If ambiguous, check receipts/existing submissions before retrying. Save screenshot, URL/ID, count, novelty results, file hashes and visible methods. No success receipt means pending/failed, not submitted.

Report success, submitted batch, review link and pending experimental selection. For preflight-only requests, provide reviewed files/manual steps without uploading.
